# Мультиплеер: как это устроено и как выложить сервер

## Коротко

* Сервер — та же программа `osil_server`, что и раньше, только теперь она ещё и слушает
  HTTP-порт. Мир на сервере и у клиента строится из одного сида, поэтому по сети ездят
  не чанки, а только игроки и правки мира.
* Клиент раз в 100 мс отправляет своё состояние (где стоит, куда смотрит, с какой
  скоростью идёт, в какой фазе замах, что в руках) и накопленные правки мира, а получает
  всех остальных и правки, которых у него ещё нет.
* Меню игры — браузер серверов: первая строка «Одиночная игра» запускает локальный мир
  без сети, остальные строки — адреса, которые игрок добавил кнопкой «Добавить сервер».

## Протокол

Обычный HTTP/1.1, тела — JSON. Так сделано намеренно: бесплатные хостинги выпускают
наружу ровно один HTTP-порт и требуют health-check, а свой UDP туда не пролезет.

| запрос | что делает |
|---|---|
| `GET /` | карточка сервера: имя, карта, сколько игроков, сид. Он же health-check |
| `POST /join` | вход: `{"name":"игрок"}` → `{"id":7,"seed":...,"head":...}` |
| `POST /sync` | обмен: своё состояние + свои правки → чужие состояния + чужие правки |
| `POST /leave` | выход: `{"id":7}` |

Формат состояния и правок — `src/Net/Protocol.h`, реализация обмена — `src/Net/Http.cpp`.

## Выкладка на render.com

В корне репозитория лежат `Dockerfile` и `render.yaml`, больше ничего не нужно:

1. В панели Render: **New → Blueprint**, указать этот репозиторий и ветку.
2. Render соберёт образ (в нём собирается только `osil_server`: SDL и OpenGL серверу не
   нужны) и запустит его. Порт он выдаёт сам через переменную `PORT` — сервер её читает.
3. Проверка живости идёт на `/`; открыв адрес сервиса в браузере, вы увидите карточку
   сервера — это и есть признак, что всё работает.
4. Имя сервера в списке задаётся переменной `SERVER_NAME` (в `render.yaml` уже есть).

## Важное ограничение: https

Render отдаёт сервисы по **https**, а TLS в клиент игры не встроен (это отдельная
зависимость, которая заметно раздувает APK и время сборки). Поэтому:

* адрес вида `https://...onrender.com` игра пока **не** откроет — она честно скажет
  «https пока не поддержан»;
* по http работает всё: сервер, поднятый на своей машине, в локальной сети, на VPS или
  на любом хостинге, который разрешает http.

Как это будет закрыто: клиенту нужен TLS-транспорт (на Android — через системный
`HttpsURLConnection` по JNI, на настольной сборке — через mbedTLS). Протокол при этом
не меняется: меняется только то, как открывается соединение.

## Запуск сервера у себя

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --target osil_server -j
PORT=28015 ./build/bin/osil_server
```

Дальше в игре: **Добавить сервер** → `адрес:28015` → **Играть**.

## Чего сервер пока не делает

* не проверяет движение игроков (клиент авторитарен для себя) — это защита от читов, и
  она приедет вместе с серверной симуляцией;
* не сохраняет постройки на диск: журнал правок живёт в памяти и теряется при
  перезапуске сервиса;
* не синхронизирует инвентарь и добычу: ресурсы у каждого свои.
