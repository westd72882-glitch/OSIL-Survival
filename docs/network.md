# Мультиплеер: как это устроено и как выложить сервер

## Коротко

* Сервер — та же программа `osil_server`, что и раньше, только теперь она ещё и слушает
  HTTP-порт. Мир на сервере и у клиента строится из одного сида, поэтому по сети ездят
  не чанки, а только игроки и правки мира.
* Клиент раз в 100 мс отправляет своё состояние (где стоит, куда смотрит, с какой
  скоростью идёт, в какой фазе замах, что в руках) и накопленные правки мира, а получает
  всех остальных и правки, которых у него ещё нет.
* Меню игры — браузер серверов: первая строка «Одиночная игра» запускает локальный мир
  без сети, остальные строки — адреса, которые игрок добавил кнопкой «Добавить сервер».

## Протокол

Обычный HTTP/1.1, тела — JSON. Так сделано намеренно: бесплатные хостинги выпускают
наружу ровно один HTTP-порт и требуют health-check, а свой UDP туда не пролезет.

| запрос | что делает |
|---|---|
| `GET /` | карточка сервера: имя, карта, сколько игроков, сид. Он же health-check |
| `POST /join` | вход: `{"name":"игрок"}` → `{"id":7,"seed":...,"head":...}` |
| `POST /sync` | обмен: своё состояние, правки и события → чужие состояния, правки и события |
| `POST /leave` | выход: `{"id":7}` |

Формат состояния, правок и событий — `src/Net/Protocol.h`, реализация обмена —
`src/Net/Http.cpp`.

## Что ездит по сети

Кроме позиций игроков и правок блоков есть **события** — то, что происходит разово и
блоками не описывается:

| событие | что синхронизирует |
|---|---|
| `Drop` / `Pickup` | выброшенные предметы: у всех лежит один и тот же куб, поднял один — исчез у всех |
| `TreeFell` | срубленное дерево. По сети уходит ОДНА точка, а валит дерево каждый у себя: мир детерминирован, значит и куски совпадут. Иначе на каждое дерево уезжало бы под сотню правок блоков |
| `Explosion` | взрыв гранаты: осколки видят все, урон каждый считает себе сам по расстоянию |
| `Hit` | удар по игроку: топор 20, факел 10, кулак 5. Урон применяет тот, по кому попали — своё здоровье считает только он |

Вошедшему позже сервер отдаёт состояние мира: что лежит на земле и какие деревья уже
срублены (последние — «молча», без анимации падения). Разовые события — взрывы и удары —
новичку не повторяются: им незачем греметь второй раз.

## Выкладка на render.com

В корне репозитория лежат `Dockerfile` и `render.yaml`, больше ничего не нужно:

1. В панели Render: **New → Blueprint**, указать этот репозиторий и ветку.
2. Render соберёт образ (в нём собирается только `osil_server`: SDL и OpenGL серверу не
   нужны) и запустит его. Порт он выдаёт сам через переменную `PORT` — сервер её читает.
3. Проверка живости идёт на `/`; открыв адрес сервиса в браузере, вы увидите карточку
   сервера — это и есть признак, что всё работает.
4. Имя сервера в списке задаётся переменной `SERVER_NAME` (в `render.yaml` уже есть).

## https: как это работает

Облачные хостинги (render.com в том числе) выпускают наружу только TLS-порт и
перенаправляют http на https. Клиент это умеет, и своей криптографии в игре при этом нет
— используется системная:

* **Android** — Java `HttpsURLConnection` через JNI (`android/.../Https.java`,
  `src/Net/Http.cpp`). Он есть в любой прошивке, тянет системные корневые сертификаты и
  ничего не весит в APK;
* **настольная сборка** — OpenSSL, если он нашёлся при сборке (в CI и на Linux он есть).
  Не нашёлся — сборка не ломается, просто https в ней не открывается.

Ещё клиент сам ходит по перенаправлениям (301/302/307/308) и разбирает ответы,
присланные кусками (`Transfer-Encoding: chunked`) — прокси хостингов отвечают именно так.

**Как игрок вводит адрес.** Достаточно имени:

* `osil-survival.onrender.com` — доменное имя без порта считается облаком, клиент сразу
  пробует `https://…:443`;
* `91.201.10.5` или `192.168.1.50` — голый IP считается своим сервером, клиент идёт на
  `http://…:28015`;
* если угадать не удалось, пробуется второй вариант;
* явные `http://`, `https://` или `:порт` отключают подбор — идём точно туда, куда сказали.

## Запуск сервера у себя

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --target osil_server -j
PORT=28015 ./build/bin/osil_server
```

Дальше в игре: **Добавить сервер** → `адрес:28015` → **Играть**.

## Чего сервер пока не делает

* не проверяет движение игроков (клиент авторитарен для себя) — это защита от читов, и
  она приедет вместе с серверной симуляцией;
* не сохраняет постройки на диск: журнал правок живёт в памяти и теряется при
  перезапуске сервиса;
* не синхронизирует инвентарь: ресурсы у каждого свои;
* не проверяет урон: и удар, и взрыв считает клиент, а жертва применяет его себе.
