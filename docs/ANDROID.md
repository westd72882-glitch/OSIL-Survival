# Android-клиент: сборка, управление, релизы

Основная платформа игры — телефон. Движок перенесён из A.N.O.D.E: SDL2 + OpenGL ES 3.0,
Java здесь ровно столько, сколько требует SDL (одна активность на десять строк), вся игра
нативная.

## Где что лежит

```
android/
├── settings.gradle.kts          проект Gradle
├── build.gradle.kts
├── gradle.properties            имя приложения и версия — один источник правды
└── app/
    ├── build.gradle.kts         SDK 34, minSdk 24, ABI arm64-v8a + armeabi-v7a
    └── src/main/
        ├── AndroidManifest.xml  требование GLES 3.0, ландшафтная ориентация
        ├── java/com/osil/survival/MainActivity.java   загрузка нативных библиотек
        ├── cpp/CMakeLists.txt   тянет SDL2/image/ttf/mixer, собирает libmain.so
        ├── res/mipmap-xxhdpi/   иконка
        └── assets/              пусто: картинки берутся из общей папки assets/ в корне
```

Исходников игры в `android/` НЕТ: `cpp/CMakeLists.txt` собирает то же дерево `src/`
(Core, World, Engine, Client), что и настольная отладочная сборка. Копий кода нет — иначе
они разъезжаются на второй же неделе.

## Что попадает в APK

| Часть | Откуда |
|---|---|
| `libmain.so` | `src/Core` + `src/World` + `src/Engine` + `src/Client` |
| `libSDL2*.so` | FetchContent из репозиториев libsdl-org (теги зафиксированы) |
| Java-обвязка SDL | клонируется в CI из того же тега SDL |
| Иконка | `android/app/src/main/res/mipmap-xxhdpi/ic_launcher.png` |
| Текстуры и иконки интерфейса | папка `assets/` в корне репозитория |

Папка `assets/` подключена в `android/app/build.gradle.kts` вторым каталогом ассетов
(`assets.srcDirs("src/main/assets", rootProject.file("../assets"))`), поэтому APK и
настольная сборка берут одни и те же файлы — копии внутри `android/` не заводим. Готовит
их `tools/prepare_assets.py` (см. `docs/VOXELS.md`), весит набор меньше мегабайта.

Ассеты при этом необязательны: шрифт берётся системный (Roboto), а если картинки не
положить, блоки рисуются цветом, кнопки — кругами со знаком из примитивов, и игра всё
равно запускается. Это осознанное решение: сборка не падает из-за отсутствия файла.

## Управление (сенсор)

Подписей на кнопках нет — только иконки: текст на круге в 60 пикселей всё равно не
читался, а на телефоне место дороже. Ниже — что какая делает.

| Жест / кнопка | Действие |
|---|---|
| Палец на **левой** половине экрана | джойстик движения — появляется там, где коснулись |
| Перетаскивание по **правой** половине, мимо кнопок | обзор |
| Кирка | сломать блок под прицелом (держать) |
| Галочка | поставить блок из выбранной ячейки пояса |
| Ладонь | съесть выбранное или напиться, стоя в воде |
| Стрелка вверх | прыжок (тратит выносливость) |
| Бегущий человек | тумблер бега (тратит выносливость) |
| Стрелка вниз | тумблер приседа |
| Ячейки пояса внизу экрана | выбрать блок или предмет |
| Рюкзак / молоток / прицел / шестерёнка | инвентарь на 30 слотов, рецепты, карта острова, настройки |
| Кнопка «назад» | закрывает окно; из игры уводит в главное меню; из меню — выход |

Сверху идёт **компас** со сторонами света и курсом в градусах — по нему в кооперативе
договариваются о направлении, как в Rust. Название блока под прицелом не выводится:
подпись висела в центре экрана постоянно и мешала смотреть; что за блок — видно по
цвету, что удар засчитан — по рамке и полосе добычи.

**Карта** — во весь экран, сетка 10×10 с подписью квадрата прямо в самом квадрате
(A1 … J10; подписи прижаты к краям экрана, чтобы не уезжать за карту). Масштаб меняется
**щипком двумя пальцами**, карта двигается перетаскиванием; кнопок приближения нет.
Закрыть — крестиком в углу или системной кнопкой «назад». Игрок показан своей меткой,
повёрнутой по курсу (сама картинка нарисована «носом вверх»); с приближением метка
подрастает, но не бесконечно — предел не даёт ей закрыть квадрат.

**Метки на карте:** короткое касание по карте ставит флажок, касание по уже стоящему
флажку его снимает. Перетаскивание и щипок метку не ставят — только касание, которое
почти не сдвинулось и быстро отпущено. Рельеф на карту не наносится: полосы ям и склонов мешали читать
границы зон, а высоту всё равно видно в игре.

**Компас** — белая полупрозрачная шкала градусов вверху экрана: деления и стороны света
едут вместе с поворотом, а неподвижная палка по центру показывает, на какой курс смотрит
игрок (число под ней).

**Крафт** — список с прокруткой пальцем: рецептов со временем станет несколько десятков,
и они не влезут ни в один экран телефона.

**Главное меню** с кнопками «Играть», «Настройки» и «Выход» открывается при запуске;
фон — картинка `assets/menu_bg.png`, вписанная по накрытию (пропорции сохраняются, лишнее
срезается по длинной стороне).

**Настройки** — не окно поверх игры, а отдельная сцена во весь экран: шапка с заголовком,
крестик выхода в правом верхнем углу и список строк почти во всю ширину. Окно было
слишком мелким для пальца, и его края путались с игрой под ним.

Почему так, а не иначе:

* **Джойстик динамический** и небольшой (15 мм): фиксированный заставляет искать его
  глазами, а прежние 22 мм занимали четверть экрана — большой палец не доставал до края
  зоны, и движение упиралось в половину скорости.
* **Джойстик не залипает.** Новое касание слева всегда перехватывает управление, а при
  сворачивании игры и при открытии окна все касания принудительно отпускаются: иначе
  система «съедает» отпускание пальца, и персонаж продолжает идти сам.
* **Шаг по блокам сглажен**: подъём на блок и спуск на ступень вниз камера догоняет за
  ~0.12 секунды, поэтому лестница из блоков не выглядит чередой рывков и падений.
* **Бег и присед — тумблеры.** Держать палец на кнопке бега невозможно, если этой же
  рукой крутить камеру.
* **Размер кнопок задан в миллиметрах**, а не в пикселях: одна и та же кнопка на
  телефоне и планшете должна быть одинаковой под пальцем.
* **Зона нажатия на 25% больше нарисованной кнопки:** промах по краю в бою читается как
  «игра не отреагировала».
* **Половины экрана разделены строго**: слева только движение, справа только обзор.
  Палец, не попавший в джойстик, раньше доставался обзору где угодно — и камера ехала
  от касания по левой половине и по интерфейсу.
* **Проверка попадания в кнопку идёт до обзора**, иначе нажатие дёргает камеру. Блок
  ломается только кнопкой «КОПАТЬ» — касание пустого места ничего не добывает.
* **Касания не превращаются в события мыши** (`SDL_HINT_TOUCH_MOUSE_EVENTS=0`, плюс
  отбрасывание событий с `SDL_TOUCH_MOUSEID`). По умолчанию SDL на Android дублирует
  каждое касание ещё и мышью — из-за этого один палец одновременно крутил камеру и
  держал «копать». Правила зафиксированы тестами (`tests/test_input.cpp`), которые
  идут без окна и без графики.
* **Кнопки можно расставить самому**: настройки → «Расставить кнопки под свою руку»,
  дальше кнопки таскаются пальцем, «ГОТОВО» сохраняет. Приём перенесён из A.N.O.D.E:
  разные телефоны и разный хват — единственная раскладка не подходит всем, а неудобная
  кнопка в выживании стоит жизни. «Сбросить раскладку» возвращает стандартную.
* **Перенос предметов — в два касания**, а не перетаскиванием: на телефоне палец
  закрывает собой ячейку, и классический drag&drop промахивается мимо цели.

На ПК (отладочная сборка) то же самое доступно мышью и клавиатурой: WASD, Space, Shift,
Ctrl, E, ЛКМ, Tab, C, M.

## Настройки производительности

`Quality` (Турбо / Низкое / Среднее / Высокое) влияет на:

| | Турбо | Низкое | Среднее | Высокое |
|---|---|---|---|---|
| Разрешение рендера | 0.42 | 0.55 | 0.75 | 1.0 |
| Предел текстур | 256 | 512 | как есть | как есть |
| Дальность прорисовки | 0.55 | 0.75 | 0.90 | 1.0 |
| Множитель дальности прорисовки | 0.55 | 0.75 | 0.90 | 1.0 |

Сама дальность задаётся отдельной строкой настроек (48 / 80 / 112 / 160 / 208 метров, то
есть от 3 до 13 чанков) — на одном телефоне хочется видеть далеко и терпеть 30 кадров,
на другом наоборот. Качество эту дальность дополнительно поджимает своим множителем.

Плюс потолок кадров (30/60/120/без ограничения): на телефоне 30 стабильных кадров
греют корпус вдвое меньше, чем 60 рваных.

Счётчик кадров всегда в правом верхнем углу, а вертикальная синхронизация выключена:
она привязывает кадр к развёртке экрана и прячет настоящую производительность — по
счётчику видно ровно 60, даже если запас втрое больше или, наоборот, кадр не успевает.
Темп задаёт свой ограничитель (потолок кадров в настройках), он же экономит батарею.

Мир строится с шагом сетки высот 4 м, как на сервере, и занимает около полусекунды;
кубический слой (чанки 16×16) достраивается уже в игре, вокруг игрока.

## Сборка

**В CI (обычный путь).** Пуш в `main` или в ветку `claude/**` запускает
`.github/workflows/build.yml`: собираются сервер и утилиты, прогоняются тесты,
рисуется карта мира, собирается APK и всё это публикуется **в Releases** отдельной
сборкой `Сборка #N` (номер = номер запуска workflow). Артефакты не используются
сознательно — квота на них исчерпана, а релизы живут постоянно и их можно скачать
с телефона.

**Локально** (нужны Android SDK, NDK 26.3.11579264 и Gradle 8.7):

```bash
# Java-обвязка SDL (один раз)
git clone --depth 1 --branch release-2.30.6 --filter=blob:none --sparse \
    https://github.com/libsdl-org/SDL.git /tmp/sdl2
cd /tmp/sdl2 && git sparse-checkout set android-project/app/src/main/java/org/libsdl/app
mkdir -p <repo>/android/app/src/main/java/org/libsdl/app
cp android-project/app/src/main/java/org/libsdl/app/*.java <repo>/android/app/src/main/java/org/libsdl/app/

# APK
cd <repo>/android
gradle assembleDebug -PbuildNumber=1
# app/build/outputs/apk/debug/app-debug.apk
```

**Отладка без телефона.** Тот же код собирается в настольный клиент (нужны SDL2,
SDL2_image, SDL2_ttf, SDL2_mixer и заголовки GLES3):

```bash
cmake -S . -B build && cmake --build build -j
./build/bin/osil_client --debug
# снимок экрана без экрана вовсе (для проверки рендера в CI и на сервере):
SDL_VIDEODRIVER=offscreen ./build/bin/osil_client --screenshot shot.png --time 13
```

Ключи отладки (на телефоне не используются): `--screenshot <файл>` — снять кадр и выйти,
`--time <час>` — время суток, `--yaw/--pitch <градусы>` — направление взгляда,
`--overlay inventory|craft|map|settings` — открыть окно сразу, `--menu` — снять главное
меню, `--play` — пропустить меню, `--dig <N>` — выкопать колодец под игроком и опустить
его на дно (проверка, что у ямы есть стенки), `--frames <N>`, `--debug`.
