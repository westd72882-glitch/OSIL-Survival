# Сетевой протокол (проект, реализуется на этапе 2)

## Транспорт

UDP + собственный надёжный слой. TCP отпадает: при потере пакета он останавливает весь
поток до ретрансмиссии, а в шутере устаревшая позиция игрока не нужна — нужна свежая.
Каналы:

| Канал | Доставка | Что идёт |
|---|---|---|
| 0 — снапшоты | ненадёжно, последний важнее | позиции, повороты, состояния сущностей |
| 1 — события | надёжно, по порядку | выстрел, попадание, крафт, открытие двери |
| 2 — состояние | надёжно | инвентарь, здоровье, список авторизаций |
| 3 — чат | надёжно | сообщения, метки на карте |

Заголовок пакета: `[protocol_id:u16][sequence:u16][ack:u16][ack_bits:u32][channel:u8]`.
`ack_bits` подтверждает 32 предыдущих пакета одним словом — стандартный приём, чтобы не
слать отдельные подтверждения.

## Подключение

```
Клиент                                   Сервер
  │ ──── ConnectRequest(версия, steam_ticket) ────────▶ │  проверка версии, бана, лимита
  │ ◀─── ConnectAccept(client_id, seed, размер, время) ─│  мир НЕ передаётся: только сид
  │ ──── LoadComplete ────────────────────────────────▶ │  клиент построил мир из сида
  │ ◀─── SpawnPlayer(позиция, характеристики) ─────────│
  │ ◀─── Snapshot × 15 Гц ────────────────────────────│
  │ ──── UserInput × 30 Гц ──────────────────────────▶ │
```

Отказ подключения (`ConnectReject`) несёт причину: неверная версия, бан (с временем
окончания), сервер полон, неверный билет Steam.

## Ввод игрока (клиент → сервер, 30 Гц)

```c
struct UserInput {
    uint32 sequence;      // номер ввода: сервер подтверждает его в снапшоте
    uint16 buttons;       // битовая маска: вперёд/назад/влево/вправо/прыжок/присед/лежать/
                          // бег/атака/прицел/перезарядка/использовать
    int16  yaw, pitch;    // углы, квантованные (1/182 градуса)
    uint8  hotbarSlot;    // выбранный быстрый слот
    float  deltaTime;     // длительность кадра клиента (проверяется на сервере)
};
```

Сервер **не доверяет** ни позиции, ни времени: `deltaTime` зажимается, скорость и «полёт»
проверяются, расхождение больше порога — телепорт клиента к серверной позиции.

## Снапшоты (сервер → клиент, 15 Гц)

Дельта к последнему подтверждённому клиентом состоянию: шлётся только то, что изменилось.
Зона интереса — сетка 200 м: игрок получает сущности только из своих и соседних ячеек,
иначе размер пакета растёт линейно с числом игроков на карте.

```c
struct SnapshotHeader {
    uint32 serverTick;
    uint32 lastProcessedInput;  // для сверки предсказания на клиенте
    float  worldSeconds;        // время мира: сутки и погоду клиент считает сам
    uint16 entityCount;
};
struct EntityDelta {
    uint32 entityId;
    uint8  flags;               // какие поля присутствуют
    int16  x, y, z;             // квантование: 4000 м / 65536 ≈ 6 см
    uint8  yaw, pitch;          // 1.4° на единицу — для чужих игроков достаточно
    uint8  stateFlags;          // присед/лежит/плывёт/ранен
    uint8  health;              // 0..255 → 0..100
};
```

## События (RPC)

**Клиент → сервер (запросы):** `RequestAttack`, `RequestUseItem`, `RequestMoveItem`,
`RequestCraft`, `RequestCancelCraft`, `RequestBuild`, `RequestUpgrade`, `RequestOpen`,
`RequestLootMove`, `RequestCodeEntry`, `RequestRespawn`, `RequestClanInvite`, `Chat`.

Имя `Request*` выбрано намеренно: клиент **просит**, сервер решает. Никакой пакет от
клиента не сообщает результат — только намерение.

**Сервер → клиенту (уведомления):** `EntitySpawn`, `EntityDespawn`, `PlayerDamaged`
(с направлением для индикатора), `PlayerDied`, `WeaponFired` (для звука и трассера у
соседей), `StructureDamaged`, `StructureDestroyed`, `InventoryUpdate`, `CraftProgress`,
`ResearchResult`, `ClanUpdate`, `ChatMessage`, `Kicked` (с причиной).

## Лагокомпенсация

Сервер держит историю позиций всех игроков за последнюю секунду (30 срезов). При выстреле
он откатывает хитбоксы на `RTT/2 + интерполяционная задержка` стрелка и проверяет попадание
там. Иначе игрок с пингом 100 мс обязан был бы стрелять с упреждением в полкорпуса.
Откат ограничен 250 мс: дальше уже даёт «выстрел из-за угла» с точки зрения жертвы.

## Защита

- Проверка версии протокола при подключении.
- Ограничение частоты пакетов на клиента и общего трафика с адреса (защита от флуда).
- Все игровые проверки — на сервере: дальность взаимодействия, линия видимости при добыче,
  наличие материалов при крафте, право строить, доступ к замку.
- Санитарная проверка ввода: NaN/бесконечности в углах, `deltaTime` вне допустимого,
  невозможная последовательность номеров — разрыв соединения.
